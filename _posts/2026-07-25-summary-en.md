## [Flux 3 X Mimic extracts world models from video generation for robotic control.](https://bfl.ai/blog/flux-3-mimic) ⭐️ 8.0/10

Black Forest Labs, in collaboration with mimic robotics, developed FLUX-mimic, a video-action model that extracts a world representation model from the multimodal video generation foundation model FLUX 3 and deploys it to control robots. The model has been tested on real-world tasks, such as a robot arm reseating a window trim. This demonstrates a novel pathway for creating more capable and general-purpose robotic policies by leveraging the rich world knowledge already encoded in large-scale video generation models. It could significantly accelerate robot learning by bypassing the need to build world models from scratch, moving towards more scalable and data-efficient embodied AI. The extracted world model is described as being less disentangled than those from specialized representation learning approaches, which may limit its usefulness for tasks requiring deep world understanding. The collaboration specifically combined FLUX 3&\#x27;s foundation model expertise with mimic&\#x27;s strength in robot learning and deployment.

Multimodal video generation models like FLUX 3 or Sora are trained on massive datasets of videos and text, implicitly learning about physics, objects, and materials. The idea of extracting actionable policies or world models from these pre-trained video generators is an active research area in robotics, known as &quot;video generators as robot policies.&quot;

## [DBOS Blog Demonstrates Postgres LISTEN/NOTIFY Can Scale to High Throughput](https://www.dbos.dev/blog/postgres-listen-notify-scalability) ⭐️ 7.0/10

A blog post from DBOS presents benchmark results showing that PostgreSQL&\#x27;s LISTEN/NOTIFY feature can achieve a throughput of 60,000 notifications per second on a single server, challenging a previous popular belief that it does not scale. This finding corrects a misconception that was based on older performance issues which have since been addressed. This matters because LISTEN/NOTIFY is a built-in, simple mechanism for real-time communication and event-driven architectures in PostgreSQL, and proving its scalability makes it a more viable alternative to external message queues for many applications. It validates the approach of systems like DBOS that rely heavily on Postgres for core functionalities, potentially simplifying tech stacks and reducing operational complexity. The benchmark achieving 60k notifications per second was conducted on a single Postgres server, indicating significant vertical scalability. The post also references and corrects a previous, widely-discussed article from July 2025 that claimed LISTEN/NOTIFY did not scale, noting that the original article&\#x27;s claims were based on issues that have been fixed.

hackernews · KraftyOne · Jul 24, 19:05 · [Discussion](https://news.ycombinator.com/item?id=49040296)

**Background**: PostgreSQL&\#x27;s LISTEN and NOTIFY commands provide a publish-subscribe communication model within the database. LISTEN allows a client session to subscribe to a named notification channel, and NOTIFY allows another session to broadcast a message \(with an optional payload\) to all listening sessions on that channel. This feature is often used for building real-time update systems or triggering application logic in response to database changes without requiring external messaging middleware. DBOS is a system that uses PostgreSQL \(and SQLite\) as its primary runtime for building durable, stateful applications.

## [Hanwha IP Camera Login Page Leaked GitHub Admin Token, Exposing Private Repos](https://hhh.hn/hanwha-github-token/) ⭐️ 7.0/10

A security researcher discovered that the login page of a Hanwha IP camera was inadvertently leaking a GitHub personal access token with administrative privileges. This token could have been used to access and potentially modify the vendor&\#x27;s private repositories. This incident highlights a severe supply-chain security risk, where a consumer IoT device&\#x27;s firmware can expose the vendor&\#x27;s internal development infrastructure. It underscores the systemic issue of poor security practices in the IoT industry, potentially compromising not just the device but the entire software supply chain for that vendor. The leaked token was embedded within the camera&\#x27;s web interface, likely a development artifact mistakenly left in the production firmware. While the specific scope of the token is unknown, GitHub admin tokens can grant extensive access to an organization&\#x27;s repositories, settings, and members.

hackernews · hhh · Jul 24, 11:54 · [Discussion](https://news.ycombinator.com/item?id=49034292)

**Background**: GitHub personal access tokens \(PATs\) are used for programmatic access to GitHub resources, such as repositories. An admin token typically has broad permissions, including read/write access to private code and potentially the ability to modify organization settings. IoT devices like IP cameras often run custom firmware, which is software developed by the vendor and can contain unintended remnants from the development process, such as hardcoded credentials or API keys.
